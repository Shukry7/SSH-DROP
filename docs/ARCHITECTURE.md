# Architecture

## Session transfer queue (0.2.0-alpha.4)

Main owns a bounded queue of at most 100 active/waiting files. Native pickers provide local paths; batch download IPC accepts only bounded, validated remote-file paths. Jobs capture their selected destinations and execute sequentially through the existing verified transfer/recovery code. Waiting cancellation never opens a source or changes a destination. A failed active job pauses remaining work until a main-owned native confirmation; failed files are not automatically retried. Recovery inspection remains available while paused. Connection changes discard the queue and suppress late old-session completions; nothing is persisted or replayed. Queue state sent to the renderer contains only counts/flags, and session transfer updates contain display filenames/status.

File/folder mutation and explorer navigation stay locked while work remains queued. Native selection is serialized and checks its connection lease after returning. Batch destinations reject case/Unicode-normalization collisions within a selection; Windows batch downloads also reject reserved device names, alternate-stream syntax and invalid local filenames. These are conservative checks, not a claim to model every filesystem's naming rules. Existing overwrite confirmations and source/destination verification remain authoritative when each file starts.

The React renderer owns presentation. A sandbox-compatible preload exposes individual methods, never raw IPC. Electron main validates the sender and every request, owns SSH connections, and opens native file dialogs. Core SSH/SFTP and trust services have no Electron dependency and are exercised over real SSH protocol in regression tests.

One SSH connection provides an independent shell channel and SFTP channel. Terminal output pauses above a bounded pending-data threshold until xterm acknowledges rendering it; stale session events cannot clear a newer shell. The explorer has an explicit absolute POSIX path. It never guesses a terminal's working directory. Local paths use local OS path rules.

Host keys are compared by host and port. Unknown keys require explicit native confirmation; changed keys are rejected. The local trust file is atomically replaced. Credentials are session-only. Private-key selection uses a native file picker and an opaque handle; the renderer cannot request arbitrary local file reads.

Saved profiles use a versioned, validated `profiles.json` in Electron's user-data directory. Operations are serialized within the app and writes atomically replace the file. Up to 100 profiles and 1 MB of UTF-8 data are supported. Invalid or unsupported data blocks profile operations without overwriting it; unsaved connections remain available. The renderer sends opaque native-picker key handles when saving, and receives a fresh handle when loading. Only main stores the key-file path; neither key contents nor passwords/passphrases are persisted. Deletion requires native confirmation and removes only the profile, preserving key files and host trust.

Transfers reserve one of two slots before asynchronous setup and stream with backpressure. Each uses an exclusive mode-0600 `.sshdrop-<UUID>.part` sibling file. Uploads verify remote readback against the streaming SHA-256; downloads verify local readback. Source metadata/size changes block publication. Upload publication uses standard SFTP rename without the overwrite extension; download publication uses an exclusive local hard link followed by temporary-link cleanup. Hard-link-unsupported destinations fail safely. Setup/finalization requests have 30-second deadlines; data progress resets a two-minute inactivity deadline; cleanup has a shared three-second budget. Missing publication acknowledgment is uncertain: never delete the final path or repeat publication. Failed/cancelled transfers attempt only their own temporary cleanup, which can fail or leave late/orphaned temporary files. Generic notices survive reconnect in memory while transfer filenames and terminal history clear. There is no automatic replay, resume, automatic recovery, or automatic recursive cleanup. Version 0.2.0-alpha.4 folder copies use the bounded planner described below.

electron-vite bundles application processes; electron-builder creates platform artifacts. The application version comes from package.json through Electron metadata. No backend, remote agent, or local PTY is required for a remote SSH shell.

## Bounded folder copies (0.2.0-alpha.4)

A main-owned folder flag extends the sequential queue; the renderer receives no new local-path capability. Dedicated upload/download-folder IPC methods validate canonical remote paths, serialize native selection and default-Cancel warnings, and check the connection lease after both. Folder copies scan before writing: at most 100 items including the root, 16 levels, 10 GiB, and a 30-second scan budget. Names are validated as portable components and siblings reject NFC/case collisions. Local scans use bounded directory reads; remote reads retain the directory service’s entry/byte/batch limits. Links, local hard-linked files and special files are refused.

The root destination must not exist. Directories are created exclusively with requested mode 0700. Empty folders are included. Before each item, canonical source/target ancestors and recorded metadata are rechecked; every file uses existing exclusive staging, hash readback and no-replace publication. No overwrite or backup approval is bypassed: existing folder roots or newly appeared file destinations fail rather than merge. Sources are read when the job runs, not snapshotted at selection. New entries added after scanning are not included. Progress is aggregate bytes for one folder job. Cancellation/failure pauses the remaining queue and preserves completed results for inspection, with no automatic recursive removal or replay. No directory timestamps, ACLs, ownership or executable permissions are preserved.

These path/metadata checks detect many concurrent changes but cannot provide atomic directory-handle-relative confinement through SFTP v3, detect hidden remote hard links, or prevent a privileged/concurrent writer swapping paths between checks and requests. Users must stop other writers and use trusted local/remote parent folders. A lost mkdir acknowledgment may leave an empty folder; inspect before retrying.
